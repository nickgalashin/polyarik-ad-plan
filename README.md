# План рекламы Полярика

Дашборд заказов и план рекламы на 01.10.2026–30.09.2027.

- «За 5 лет» — топ-7 за май 2022 — сентябрь 2026.
- «За год» — топ-7 за 22.09.2025 — 22.09.2026.
- «План рекламы» — топы последнего года, перенесённые на месяц раньше.

Открывайте `index.html#plan` для перехода сразу к плану рекламы.
Под каждым месяцем кнопка «+ Добавить поле» добавляет товар, задачу или комментарий.
Все рейтинги, общие заметки и журнал действий находятся в `plan-data.json`.
При открытии страница загружает JSON, затем запрашивает свежую версию через
GitHub Contents API. Кнопка «Обновить общие данные» обновляет заметки вручную.
У подключённых редакторов обновление работает каждые 30 секунд, пока вкладка видима.

## Общая запись через GitHub

GitHub Pages публикует файлы и позволяет их читать, но сам не принимает запись.
Изменения записываются в `plan-data.json` в ветке `main` через GitHub Contents API.
Дополнительный хостинг или база данных для этого варианта не нужны.

Каждому редактору нужен свой аккаунт GitHub с правом записи в
`nickgalashin/polyarik-ad-plan` и личный fine-grained token, ограниченный этим
репозиторием, с разрешением **Contents: Read and write**.
Токен создаёт сам пользователь в GitHub Settings → Developer settings →
Personal access tokens → Fine-grained tokens. Настройте срок действия.
Затем откройте «Доступ для редактирования» на странице и подключите токен.
Он не сохраняется в localStorage, cookies, JSON или исходном коде: только в памяти
открытой страницы, а передаётся только на `https://api.github.com`.
После перезагрузки требуется подключение заново. Обычный вход в GitHub в соседней
вкладке не заменяет API-токен. Кнопка «Отключить» очищает токен из памяти.
Кнопки «Добавить поле» и «Изменить» доступны без подключения: нажатие открывает
панель доступа и объясняет необходимость токена. Общая запись по-прежнему
разрешена только редактору; отключённый доступ не обходится.

Добавление и удаление сохраняются сразу; ввод — через 1,5 секунды после паузы
или при выходе из поля. Успешная запись подтверждается сообщением сверху.
После сохранения непустая ручная запись отображается белой строкой под топ-7.
Кнопка «Изменить» возвращает текстовое поле; удаление доступно рядом со строкой.
Сохранённые ручные записи добавляются после топ-7 в список каждого календарного
месяца и в окно выбранного дня. Счётчик списка включает их. Новые черновики
попадают в календарь только после успешного сохранения; изменения других
сотрудников обновляют строки и календарь при загрузке общей версии JSON.
Ошибки доступа/сети не выдаются за успешное сохранение. Несохранённый текст
остаётся в полях и попадает в экспорт как `unsavedDrafts`, но не записывается в
хранилище браузера; при закрытии страницы с черновиками показывается предупреждение.

## Формат JSON и действия

- `version`, `period`, `revision`, `updatedAt` — версия формата, период и состояние.
- `rankings.full`, `rankings.year` — первоначальные исторические топы без изменений.
- `notes` — массив полей со стабильными `id`, `month` (0–11), `text`, `revision`,
  `updatedBy`, `updatedAt`.
- `actions` — журнал `add`, `edit`, `delete`: идентификатор операции, поле, месяц,
  GitHub-автор, время UTC, прежний/новый текст и ревизия.

Изменения отправляются последовательно. Перед записью читается свежий JSON и SHA.
При изменении файла другим сотрудником запрос повторяется со свежей версией до
трёх раз. Операции имеют ID, чтобы повторная отправка не дублировала действие.
Правки разных полей объединяются. Если изменилась ревизия того же поля, чужая
версия не перезаписывается; рядом с вашим черновиком показывается общий текст.
Можно скопировать черновик и принять общую версию для нового редактирования.
Журнал интерфейса показывает последние 100 действий; файл содержит всю историю.
Это журнал приложения, который редакторы репозитория могут изменить напрямую;
GitHub также хранит историю коммитов.

Экспорт скачивает весь JSON с историей. Импорт принимает формат v2 и прежние
экспорты v1. Он **добавляет** заметки и регистрирует добавления от имени текущего
редактора; существующие записи и журнал не заменяются чужим экспортом.
Для миграции старых заметок из браузера есть отдельная кнопка скачивания прежнего
экспорта: затем импортируйте его в общий JSON после подключения GitHub.

JSON ограничен размером 900 КБ из-за выбранного способа чтения Contents API.
При достижении лимита потребуется архивирование истории администратором.
API имеет собственные лимиты. Частые автосохранения создают коммиты и могут
запускать сборку Pages; этот вариант предназначен для небольшой команды.
Официальная документация: https://docs.github.com/en/rest/repos/contents

Календарь содержит 365 дней: 1–14 число каждого месяца — подготовка, с 15 числа
до конца месяца — запуск. Нажмите на день для просмотра топ-7 и заметок месяца.

## Размещение

Статический сайт без сборки. В GitHub Pages выберите Deploy from a branch,
ветку `main`, папку `/ (root)`.

Запрет индексации задан через meta robots, googlebot и yandex в `index.html`,
а также `robots.txt`. Доступ по ссылке остаётся открытым. Репозиторий и JSON
публичны: общие заметки и история не являются закрытыми данными сотрудников.

## Проверка

Проверены сдвиг всех 12 месячных топов, календарь 01.10.2026–30.09.2027
(168 дней подготовки и 197 дней запуска), переходы между вкладками и мобильная вёрстка.
JSON-модель: `node --test model.test.cjs` проверяет CRUD, журнал,
защиту от устаревших правок, объединение независимых действий, повтор операции
и валидацию. В браузере с локальной имитацией GitHub API проверены два
редактора, подгрузка общей записи, сохранение, конфликт и удаление.
Запись реальным API требует личного токена редактора и не проверена тестовым токеном.

Индивидуальные сроки: нажмите название товара в топ-7 или сохранённой ручной строке. Окно задаёт начало/окончание подготовки и запуска, допускает сдвиг всего графика. Сроки по умолчанию: 1–14 и 15–конец месяца. Общий JSON содержит необязательный массив schedules со стабильными ключами top:месяц:позиция / note:id, revision и автором. Изменения сроков входят в actions; конкурентная правка того же товара требует загрузки актуальных дат. Удаление ручной строки удаляет её график. Календарь показывает пересекающиеся графики разных месяцев, а окно дня — только активные этапы. Сохранение использует прежние права GitHub. При публикации кода не заменяйте plan-data.json, чтобы сохранить общие пользовательские данные.
